# 02-design — требования к дизайну Delivery

Этот документ — **бриф для Pencil.dev**. Он описывает, что нужно нарисовать, в каком порядке, в какой стилистике и с какими ограничениями. Источник правды по бизнес-логике — [`01-requirements/README.md`](../01-requirements/README.md) и диаграммы в [`01-requirements/diagrams/`](../01-requirements/diagrams/).

> **Контекст продукта:** Delivery — маркетплейс с доставкой по России. Веб (адаптивный) + мобильное приложение (React Native). Бэкенд один на оба клиента. Подробнее — корневой [`README.md`](../README.md).

---

## 0. Порядок работы — ЭТО ВАЖНО

Дизайн делится на **две последовательные фазы**. Не начинать фазу 2, пока фаза 1 не согласована.

### Фаза 1 — Дизайн-система (DS)
Сначала собираем **дизайн-систему**: токены, базовые компоненты, состояния, типографика, сетка. Без неё не рисуем ни одного экрана.

**Критерий готовности фазы 1:**
- все компоненты из раздела 4 ниже существуют в Pencil как переиспользуемые;
- цветовые токены покрывают светлую и тёмную темы;
- собран демо-экран (UI-kit) со всеми компонентами в одном месте — для ревью;
- демо-экран **согласован с владельцем продукта**.

### Фаза 2 — Экраны продукта
Только после согласования DS — собираем экраны из раздела 5, **используя исключительно компоненты из DS**. Новые произвольные стили в экранах не допускаются: если чего-то не хватает — возвращаемся в DS, добавляем компонент, продолжаем.

## 1. Платформы и адаптивность

Дизайн нужен под **три формата**:

| Формат | Назначение | Ширина |
|--------|-----------|--------|
| Desktop Web | Next.js, основной веб | контент-контейнер **до 1100px**, дальше — поля |
| Mobile Web | тот же Next.js, мобильный браузер | до **800px** ширины |
| Mobile App | React Native (iOS/Android) | стандартные размеры телефона (375–430pt) |

**Правила адаптивности веба:**
- **Один брейкпоинт** между desktop и mobile web (~800–900px). Не плодим промежуточные.
- Резиновая сетка: внутри своих лимитов всё тянется/сжимается.
- Отдельные мобильные версии — **только** для специфических элементов (фильтры, дроверы, шапка, корзина).
- Mobile Web и Mobile App **визуально похожи**, но Mobile App имеет нижний таб-бар вместо шапки навигации.

**Навигация: desktop vs mobile web:**
- **Desktop Web — полноценная шапка** (sticky сверху): логотип слева, горизонтальная навигация по категориям, поиск по центру (растягивается), справа — переключатель темы, иконка профиля, иконка корзины с бейджем. Всё видно сразу, без скрытых меню.
- **Mobile Web — компактная верхняя шапка** (логотип + иконка поиска + иконка корзины + иконка-бургер) и **выдвижное меню снизу (bottom sheet)** по клику на бургер. Меню выезжает с нижнего края экрана с плавной анимацией, имеет «ручку» (drag handle) сверху, перекрывается полупрозрачным оверлеем и закрывается свайпом вниз или тапом по оверлею.
- **Содержимое bottom-sheet меню:** ссылки на категории, профиль/вход, заказы, темизация, юридические страницы. По сути — мобильный аналог desktop-шапки + футера.
- На Mobile App роль такого меню играет нижний таб-бар, отдельный bottom-sheet не нужен.

## 2. Бренд и стилистика

### Референс — shadcn/ui
Базовая визуальная и поведенческая модель — **[shadcn/ui](https://ui.shadcn.com)**. Это не «копировать один в один», а **отправная точка**: берём оттуда геометрию компонентов, состояния, плотность интерфейса, поведение dialog/sheet/dropdown — и дальше адаптируем под наш «облачный» стиль (см. ниже).

**Почему это важно:** фронт будет писаться **на shadcn/ui** (Next.js + Tailwind + Radix), поэтому чем ближе дизайн к нативным компонентам shadcn по API и состояниям — тем дешевле перенос дизайна в код через Pencil MCP.

**Что берём от shadcn как есть:**
- структуру и состояния базовых компонентов (Button, Input, Dialog, Sheet, DropdownMenu, Tabs, Accordion, Toast, Tooltip, Skeleton);
- идею токенов через CSS-переменные (`--background`, `--foreground`, `--primary`, `--muted`, `--border`, `--ring` и т.п.) — наши токены маппятся на этот набор;
- focus-ring через `--ring`, единый для всех интерактивных элементов;
- размерную шкалу (sm / md / lg) и общую плотность.

**Что меняем под наш бренд:**
- акцент — наш **голубой**, а не дефолтный shadcn-чёрный/zinc;
- скругления — крупнее дефолтных shadcn (наш `radius-md` ≈ 12px против 6–8px у shadcn по умолчанию);
- тени — **мягче и заметнее**, у shadcn они почти отсутствуют, у нас — это часть «облачного» стиля;
- фон страницы — слегка серый, не чисто белый;
- карточки — с собственной поверхностью, тенью и скруглением, более «модульные», чем дефолтные shadcn-Card.

### Общая идея
- **«Облачный» модульный стиль:** карточки, блоки, плитки с собственными скруглениями и мягкими тенями.
- **Светло, воздушно, современно.** Не плоско, но и не скевоморфно.
- Возможен **плиточный** дизайн (Bento-стиль) для главной и витрин.

### Цветовая палитра

**Светлая тема (по умолчанию):**
- Фон страницы — слегка **серый** (не чисто белый), чтобы белые карточки «всплывали».
- Поверхность карточек/модулей — **белый**.
- Акцент — **голубой** (основной CTA, активные элементы, ссылки).
- Текст — тёмно-серый/почти чёрный.
- Второстепенный текст — средне-серый.
- Бордеры — светло-серые, тонкие.

**Тёмная тема:**
- Фон страницы — глубокий тёмно-серый (не чёрный).
- Поверхность карточек — на ступень светлее фона.
- Акцент — тот же голубой, возможно чуть ярче для контраста.
- Все цвета — через токены, тёмная тема **не отдельный набор экранов**, а альтернативные значения токенов.

**Семантические цвета (обе темы):**
- success (зелёный) — успешный заказ, статус «Завершено».
- warning (жёлто-оранжевый) — товар в пути / промежуточные статусы.
- danger (красный) — ошибка, отмена заказа.
- info (голубой = акцент) — нейтральные подсказки.

### Скругления и тени
- Скругления: токены `radius-sm` (~6–8px), `radius-md` (~12px), `radius-lg` (~16–20px), `radius-pill` (для бейджей и тегов).
- Тени: 2–3 уровня (`shadow-sm`, `shadow-md`, `shadow-lg`) — мягкие, низкоконтрастные, без жёстких краёв.

### Типографика
- Шрифт — **веб-оптимизированный** (Inter / Manrope / SF Pro / похожий, выбор за дизайнером, но один на весь продукт).
- Иерархия: H1, H2, H3, body-lg, body, caption, label, button.
- Один шрифт на всё — без декоративных вторых.

## 3. Иконки и иллюстрации

- **Иконки:** один набор (Lucide / Phosphor / Tabler — на выбор). Размеры: 16 / 20 / 24 / 32. Stroke-стиль, без заливок.
- **Иллюстрации:** минималистичные, в палитре бренда. Используются для пустых состояний (корзина пуста, нет заказов, 404).
- **Логотип:** нужно создать в рамках фазы 1. Простой, читается в светлой и тёмной теме, работает в шапке и фавиконе.
- **Аватары пользователей:** 5–10 преднастроенных вариантов, AI-сгенерированные, единый стиль (иллюстративные, не фото).

## 4. Дизайн-система — что должно быть в фазе 1

### 4.1 Токены
- **Цвета:** primary, surface, background, text-primary, text-secondary, border, success, warning, danger — с вариантами для light/dark.
- **Радиусы:** sm / md / lg / pill.
- **Тени:** sm / md / lg.
- **Spacing:** шкала 4-8 (`4, 8, 12, 16, 24, 32, 48, 64`).
- **Типографика:** размеры и line-height для всех уровней.

### 4.2 Базовые компоненты
Все — с состояниями `default / hover / active / focus / disabled` (для веба) и `default / pressed / disabled` (для мобилки).

- **Button:** primary / secondary / ghost / danger; размеры sm / md / lg; с иконкой и без.
- **Icon Button:** квадратный, для шапки и тулбаров.
- **Input:** текст, email, пароль (с иконкой «глаз»), поиск (с иконкой и крестиком очистки), с лейблом и без, с ошибкой.
- **Textarea.**
- **Select / Dropdown.**
- **Checkbox, Radio, Switch.**
- **Badge / Tag** — для бейджа корзины, скидок, статусов.
- **Counter / Stepper** — кнопка «+ / −» для количества товара в карточке и в корзине.
- **Card** — базовая карточка-контейнер (используется как основа карточки товара, заказа, пользователя в админке).
- **ProductCard** — карточка товара: картинка, название, цена, старая цена (если скидка), бейдж скидки, кнопка «Купить» / счётчик.
- **OrderCard** — карточка заказа в истории: статус-бейдж, дата, сумма, превью товаров.
- **Modal / Dialog** — со шапкой, контентом и футером с кнопками. Размер sm / md / lg.
- **Toast / Notification** — успех, ошибка, инфо.
- **Tabs.**
- **Accordion** — для админки (раскрытие пользователя со списком заказов).
- **Breadcrumbs** — навигация по каталогу.
- **Pagination** или **Infinite Scroll-loader** — выбрать одно для каталога.
- **EmptyState** — иллюстрация + текст + опциональная кнопка (пустая корзина, нет заказов, ничего не найдено).
- **Skeleton / Loader** — для загрузки карточек товара, заказов.
- **Avatar** — кружок с картинкой из набора.
- **StatusTimeline** — вертикальный/горизонтальный таймлайн 6 статусов заказа с пройденными/текущими/будущими шагами.
- **Map placeholder** — компонент-обёртка под карту выбора адреса (внутри — реальный SDK).
- **CookieBanner** — нижний баннер.

### 4.3 Композитные блоки
- **Header (desktop):** логотип, навигация по категориям, поиск, иконка профиля, иконка корзины с бейджем, переключатель темы.
- **Header (mobile web):** логотип, иконка поиска, иконка корзины, бургер-меню.
- **BottomTabBar (mobile app):** 4–5 вкладок (Главная, Каталог, Корзина с бейджем, Заказы, Профиль). С плавными анимациями переходов.
- **Footer:** ссылки на «О магазине», политику ПД, политику cookies; копирайт.
- **SearchInput с дропдауном:** поведение при фокусе (популярные товары) и при вводе (autocomplete).
- **CategoryNav:** горизонтальный список категорий/подкатегорий.

### 4.4 UI-kit экран
Один сборный экран в Pencil, на котором показаны **все** компоненты выше во всех состояниях. Это артефакт ревью фазы 1.

## 5. Экраны продукта — фаза 2

Все экраны рисуются в **трёх версиях**: Desktop Web, Mobile Web, Mobile App. Mobile Web и Mobile App могут отличаться только навигацией (таб-бар vs шапка) и нативными жестами.

### 5.1 Публичные экраны (гость и клиент)
1. **Главная**
   - Шапка + поиск с дропдауном популярных при фокусе.
   - Блок витрин: «Популярные», «Сезонные», «Со скидкой» — горизонтальные карусели карточек.
   - Категории верхнего уровня — плиточная сетка с иконками/иллюстрациями.
   - Cookie-баннер при первом визите.
2. **Категория / подкатегория**
   - Breadcrumbs, заголовок, фильтры (цена, может быть подкатегория), сетка карточек, пагинация или ленивая подгрузка.
   - Mobile: фильтры — в дроуере снизу.
3. **Карточка товара**
   - Галерея, название, цена (со старой ценой если есть скидка), описание, счётчик количества, кнопка «В корзину» / счётчик если уже добавлен.
   - Блок «Похожие товары».
4. **Результаты поиска** — та же сетка карточек, шапка с поисковым запросом.
5. **Корзина**
   - Список товаров со счётчиком и удалением, итоговая стоимость, кнопка «Оформить».
   - Пустое состояние с EmptyState.
6. **Оформление заказа**
   - Шаги: адрес → карта → калькуляция → оплата.
   - Карта на пол-экрана (desktop) или раскрывающаяся (mobile).
   - Сводка справа (desktop) или снизу (mobile).
   - Итог: товары, доставка, срок доставки, итоговая сумма, кнопка «Оплатить» (имитация).
7. **Успех оплаты** — экран подтверждения с CTA «К моим заказам».
8. **Юридические страницы:** «О магазине», политика ПД, политика cookies — типографские страницы по единому шаблону.
9. **404 / ошибка** — EmptyState + кнопка возврата.

### 5.2 Авторизация
10. **Модалка входа/регистрации** — единая, email + пароль, тоггл «показать пароль», ошибки, ссылки на политику ПД.

### 5.3 Личный кабинет (клиент)
11. **Профиль** — имя, фамилия, телефон, дата регистрации, аватар (с кнопкой «Сменить» → модалка с выбором из набора).
12. **История заказов** — список OrderCard, фильтр по статусу.
13. **Детали заказа** — товары, адрес, сумма, **StatusTimeline** из 6 статусов, кнопка «Отменить» (активна только для `created` / `processing`).

### 5.4 Админ-панель
14. **Список пользователей** — таблица/список с поиском.
15. **Карточка пользователя (Accordion)** — раскрытие: доп. инфо + список его заказов с возможностью отменить заказ из админки.

### 5.5 Системные состояния
Для каждого ключевого экрана нужны:
- состояние **загрузки** (Skeleton);
- состояние **пустоты** (EmptyState);
- состояние **ошибки сети**.

## 6. Темизация

- Все экраны рисуются **в светлой теме**, тёмная — отдельным проходом через подмену токенов.
- Тёмная тема не должна требовать отдельной разметки или новых компонентов — только цветовые токены.
- Демонстрация переключателя темы — в шапке (desktop) и в профиле (mobile app).

---

## 7. Поведение и микро-анимации

- Hover-состояния карточек: лёгкий подъём тени (`shadow-sm → shadow-md`) и/или translate-Y -1–2px.
- Переходы между табами в мобайле — плавные слайды/кросс-фейды.
- Появление дропдауна поиска — fade + small translate-Y.
- Изменение количества в счётчике — мгновенное, без анимации цифр.
- Бейдж корзины — короткий bump при добавлении товара.

---

## 8. Что НЕ нужно рисовать

- Реальный интерфейс платёжной формы — только кнопка «Оплатить» и экран успеха (оплата имитируется).
- Интерфейс курьера — роли нет.
- Управление товарами/категориями в админке — на старте только seed.
- Загрузка файлов пользователем (аватары — только выбор из набора).

## 9. Артефакты на выходе

После фазы 2 в проекте Pencil должно быть:
