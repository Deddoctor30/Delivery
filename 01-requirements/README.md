## 1. Концепция

**Delivery** — маркетплейс товаров с доставкой по России. Пользователь ищет товары, добавляет в корзину, оплачивает (на первом этапе — имитация оплаты), курьер доставляет. Срок доставки зависит от удалённости от Москвы.

### Ключевые принципы
- **Современный стек** и современные практики разработки.
- **AI-инструменты** интегрированы в рабочий процесс (генерация дизайна → код через Pencil MCP).
- **Ориентация на пользователя:** быстрая работа, web-метрики **90+** (Lighthouse).
- **Готовность к деплою:** Docker для всех сервисов, инструкции по запуску.
- **Качество:** тесты во всех слоях, детальные README в каждом проекте.

## 2. Каталог товаров

### Категории верхнего уровня
1. **Одежда** — мужская, женская, детская.
2. **Дом и дача.**
3. **Электроника.**

### Требования к структуре
- Каждая категория верхнего уровня содержит **от 5 до 10 подкатегорий**.

### Изображения (медиа-активы)
- **Источник:** изображения товаров и набор аватаров создаются разработчиком вручную (AI вне приложения), это **не часть пользовательского флоу**.
- **Загрузка пользователем не предусмотрена** — ни товаров, ни аватаров, ни других файлов.
- **Единый источник для всех клиентов — бэкенд.** Картинки лежат в `03-backend-nestjs/static/`:
  - `static/products/` — изображения товаров;
  - `static/avatars/` — преднастроенный набор аватаров (5–10 шт).
- **Отдача:** NestJS `ServeStaticModule`, публичный URL вида `GET {API_BASE_URL}/static/products/jacket-1.webp`.
- **В БД** хранятся только относительные пути (например, `/static/products/jacket-1.webp`).
- **На клиентах:**
  - **Веб (Next.js):** `next/image` с доменом бэка в `images.remotePatterns` — Next сам оптимизирует и кэширует.
  - **Мобилка (Expo):** `expo-image` с тем же базовым URL, встроенный кэш на устройстве.
  - Никакого дублирования картинок в коде клиентов — оба ходят за одним URL.
- **Миграция в облако** (Cloudflare R2 / S3 / CDN) — меняется только конфигурация бэка (или путь монтирования volume), код клиентов остаётся прежним.

### Специальные витрины
- Поиск товаров.
- **Популярные** товары.
- **Сезонные** товары.
- Товары **со скидкой**.

## 4. Авторизация и личный кабинет

### Регистрация / вход
- **Единая модалка** для входа и регистрации.
- Если пользователь уже зарегистрирован — данные подтягиваются автоматически.
- Если нет — создаётся новый аккаунт.

### Личный кабинет
- **Профиль:** имя, фамилия, номер телефона, дата регистрации, **аватар**.
- **История заказов** со статусами.
- Возможность редактировать имя, фамилию и аватар.

### Аватары
- Загрузка пользовательских файлов **не поддерживается**.
- Пользователь выбирает аватар из **предустановленного набора** (5–10 вариантов, сгенерированы AI).
- В БД хранится только идентификатор/путь выбранного аватара.

## 5. Корзина и оформление заказа

### Корзина
- При добавлении товара на карточке — **счётчик количества**.
- В иконке корзины в шапке — **индикатор** заполненности (бейдж).
- В корзине — список всех товаров и **общая стоимость**.

### Оформление
- Поле адреса доставки + **интерактивная карта** для выбора точки.
- Автоподстановка адреса по выбранной точке на карте.
- **Калькуляция стоимости** (товары + доставка).
- Кнопка «Оплатить» — на первом этапе **имитация** успешной оплаты (касса не подключена).

## 6. Заказы и доставка

### Расчёт срока доставки
По дистанции от Москвы:
- **внутри МСК:** до 2 дней;
- **до Владивостока:** до 2 недель;
- между — пропорционально (интерполяция).

### Жизненный цикл заказа
Визуальная индикация статусов:
1. Заказ принят.
2. Обрабатывается.
3. Курьер взял товар.
4. Товар в пути.
5. Товар прибыл.
6. Завершено.

### Отмена и возврат
- Заказ можно **отменить и вернуть средства**, пока курьер **не взял товар** (т.е. до статуса «курьер взял»).

## 7. Роли и админка

### Роли
- **Гость** — не авторизован, может смотреть каталог, искать, наполнять корзину (хранится в localStorage).
- **Клиент** — авторизованный пользователь, оформляет заказы, имеет ЛК и историю.
- **Админ** — имеет доступ к админ-панели.

### Админ-панель
- Перечень **всех пользователей** платформы.
- Каждый пользователь раскрывается через **аккордеон**:
  - доп. информация о пользователе;
  - список **его заказов** с деталями (товары, статус, сумма, адрес).
- Из админки админ может **отменить заказ** пользователя (если статус позволяет).

### Симулятор смены статусов
Так как роли «курьер» нет, продвижение заказа по статусам выполняется **автоматическим cron-симулятором** на бэкенде. Тайминги переходов:

| Переход | Время после предыдущего статуса |
|---------|---------------------------------|
| `Заказ принят` → `Обрабатывается` | **1 минута** |
| `Обрабатывается` → `Курьер взял товар` | **5 минут** |
| `Курьер взял товар` → `Товар в пути` | интерполяция по расстоянию |
| `Товар в пути` → `Товар прибыл` | интерполяция по расстоянию |
| `Товар прибыл` → `Завершено` | интерполяция по расстоянию |

Интерполяция — пропорционально расчётному сроку доставки (см. раздел 6): общий срок распределяется между тремя последними переходами.

## 10. Дизайн

### Темы
- **Светлая** и **тёмная** темы.

### Цветовая палитра (светлая тема)
- Основные акценты на кнопках и элементах — **белый** и **голубой**.
- Фон — слегка **серый**.

### Стилистика
- **Лёгкий, «облачный» стиль**, **модульный**.
- Небольшие **скругления** углов.
- Модули с собственными скруглениями.
- Возможен **плиточный** дизайн.
- **Тени** для визуального отделения блоков.

### Типографика
- Шрифт, **оптимизированный для веба** (web-fonts с правильной подгрузкой).

### Адаптивность (веб)
- **Резиновый дизайн** как основа.
- **Десктоп:** контент ограничен **1100px**, далее — сжатие элементов (резинка).
- **Мобилка / планшет:** растягивается **до 800px**, выше — ограничение.
- **Один брейкпоинт** между десктоп- и мобильным макетом.
- Минимальное количество перестроений: отдельные мобильные версии — только для специфических элементов (фильтры и т.п.).

### Мобильное приложение
- Роутинг через **нижний таб-бар**.
- **Плавные анимации** переходов между экранами.

### Дизайн-система
- **Сделать до начала разработки.**
- Вынести переиспользуемые компоненты (кнопки, инпуты, карточки, модалки и т.п.).
- Source of truth — Pencil.dev, экспорт токенов в код.

## 11. Что не входит в MVP

Зафиксировано, что **на первом этапе не делаем**:
- Реальную интеграцию с платёжными системами (имитация оплаты).
- Реальный трекинг курьера (только статусы, продвижение через cron-симулятор).
- Роль «курьер» с отдельным интерфейсом.
- Управление товарами и категориями через админку (на старте — seed-скрипт).

## Решения по открытым вопросам

- **Карты:** провайдер выбирается на уровне веб-приложения (`04-web-nextjs`), решение откладывается. Бэк хранит только координаты и адрес как строку.
- **Геокодирование:** решается на стороне веба тем же провайдером карт.
- **Роль курьера:** не делаем. Статусы продвигает cron-симулятор (см. раздел 7).
- **Расчёт дистанции:** по прямой (Haversine) от координат Москвы.
- **Источник данных о товарах:** генерация сида ИИ-ассистентом по согласованной схеме. После старта `03-backend-nestjs` и фиксации Prisma-схемы ассистент создаёт seed-скрипт с категориями, подкатегориями и товарами, который заполняет PostgreSQL стартовым набором. Изображения товаров — отдельно, кладутся вручную в `03-backend-nestjs/static/products/`, в сиде используются их пути.
